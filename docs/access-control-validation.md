# 局域网门禁验证记录

本记录汇总2026-10-27的开发与板端验证，供理解测试范围；日期后的软件、设备与运行状态应重新核验。实际部署和数据备份方法见[运维说明](access-control-operations.md)。

## 已验证的内容

- 板端单路版本在开发机完成CPU构建，管理服务的39项Python回归及9组CTest通过。测试使用临时数据，覆盖认证、SQLite事件、进出配对、异常处理、人员与样本管理、身份缓存、界面和语音等功能。
- 未稳定目标的识别间隔调整为50毫秒后，开发机和RK3568的9组CTest通过。后续加入Unknown宽限与同轨迹事件补记后，开发机和板端再次通过9组CTest；板端RKNN自检报告YuNet检测和MobileFaceNet识别后端加载成功。
- MIPI启动检查记录了eglfs画面、800×600 V4L2 DMA-BUF取流、相机和识别自动启动。局域网管理首页及认证状态接口返回HTTP 200；这证明当时的启动及连接状态，不证明识别准确率。
- 管理认证曾通过自动化测试；实体键盘登录并返回值守界面经用户实机确认。屏幕软键盘方案曾在实机出现坐标偏差，当前版本已移除，需使用实体键盘。
- 历史语音版本在板端分别验证过PulseAudio/RK809和ALSA/RK809播放；语音主观效果和物理音量键仍应在目标设备上验收。

## 当前识别规则

默认配置中，未稳定目标按50毫秒间隔尝试识别；在最多5票中同一结果获得3票后形成共识。首次有效推理起3秒内，未匹配目标保持识别中，不因Unknown共识播拒绝提示或记录拒识；达到3秒且仍形成Unknown共识后才记录拒识。已知人员可在宽限期内确认。

已知身份确认后，同一条存活轨迹不再周期复查，轨迹丢失并清理后才能重新确认。如果人员在同一条未中断轨迹中发生替换，可能沿用前一个身份。轨迹若先记录拒识，后匹配到人员，会保留原拒识事件并另记允许事件；自动化回归使用临时SQLite覆盖了这一过程。

## 验证边界

- 上述自动化、公开测试图和启动检查不能替代真实登记人员的进出配对、禁用拒绝和异常处理验收，也不能推算开放集识别准确率。
- 本次调整没有做同场景真人端到端延时、FPS或识别率对照，不能据此声称实际速度或准确率提升。
- 当前未实现活体检测；普通人脸识别和光流跟踪不保证抵御照片、屏幕或视频攻击。
- 一台摄像头的站点方向可切换为进或出，但不能同时代表两个物理出入口。管理网页只用于数据库和记录管理，实时识别由板端本地摄像头完成。
- DMA-BUF导出不代表整条推理链路零拷贝。管理服务默认明文HTTP，部署时需限制网络访问；详细说明见[运维说明](access-control-operations.md)。
